# Work log — 2026-08-16

53 commits on `dev`. The day had two halves: making the fork build, launch and behave
correctly on Linux, then bringing it up on Windows for the first time. Along the way a
fair amount of dead and unsupported code came out.

Both platforms now build and pass the suite at the same commit, and the app has been run
live on Windows against a populated community server.

## Launch is stable on both platforms

Most of the day's user-visible work was in getting TF2 to actually launch, and getting
TF2BD to find the pieces it needs.

- **Steam library discovery rewritten.** Stock v1.7.0 only iterated the numeric
  *attributes* of `libraryfolders.vdf`, while a current Steam writes numbered *child
  objects* with a `path` key. On a machine with TF2 on a non-default library that meant
  `FindTFDir()` found nothing at all. Now parsed properly, with duplicate libraries
  de-duplicated (`~/.steam/steam` is commonly a symlink, so a naive parse reports the same
  library twice).
- **Linux Steam roots are probed properly** — `.steam/steam`, `.local/share/Steam`, the
  Flatpak path under `.var/app/`, and `.steam/root`.
- **The sniper runtime is searched across every Steam library**, not just the default one,
  and when it genuinely is not installed the error now says *where it looked* instead of
  rendering an empty path.
- **TF2 executable discovery unified.** One list of on-disk binary names, a separate list
  of live process names — they answer different questions and folding them together made
  the Linux process lookup latch onto the `tf.sh` wrapper instead of the game.
- **Launch options are tokenized correctly**, and an over-length command line is now
  refused with an explanation rather than silently truncated.
- **VAC override fixed.** The app used to append its own `-secure` after the user's
  forwarded options, producing `-insecure -insecure -secure`. It now yields to an explicit
  user choice.

## Windows bring-up — first time ever

The fork had never been compiled on Windows. It now is. Three defects only Windows could
expose, found by the compiler, the linker and the test suite respectively:

1. **`getenv` is fatal under `/WX`.** MSVC deprecates it (C4996) and the project treats
   warnings as errors.
2. **The CLI had no entry point.** `Launcher/main.cpp` keyed its entry point on `WIN32`,
   so on Windows it emitted only `wWinMain`. That suits the GUI launcher, which is a
   `/subsystem:windows` target, but not `tf2_bot_detector_cli`, a console exe that needs
   `main` — it failed to link. Since the CLI *is* the test runner, the Windows suite was
   structurally unrunnable rather than merely failing.
3. **argv[0] rules corrupted the first launch option.** This one was a live product
   defect, not a test artifact. `SplitCommandLineArgs` handed the raw string to
   `CommandLineToArgvW` with no program name, so the first token was parsed under argv[0]
   rules — where a leading-whitespace command line yields an empty argv[0]. Steam launch
   options beginning with a space produced a spurious empty token, on Windows and nowhere
   else. Fixed at the source rather than in the test expectations.

The `[realsteam]` integration checks also now resolve the Steam root per platform — the
registry on Windows, `$HOME` probing elsewhere — because the shared discovery function
only understands Linux layouts.

## CI and safety

- **Workflows are manual-dispatch only.** Push-triggered builds on a private repo bill
  real money per commit, and Windows runners bill at 2×.
- **`scripts/ci-local.sh`** is the local replacement: safety boundary, configure, build,
  the unit suite, and the `[realsteam]` tag, exiting with the number of failed stages. It
  runs on both platforms.
- **A safety-boundary check** enforces the architecture boundary in CI, and was fixed to
  actually catch memory-access code. Exemptions are tagged `safety-boundary-allow` and are
  greppable on purpose.
- An all-skipped `[realsteam]` run no longer counts as a failure. Catch2 treats "every test
  skipped" as "no tests ran" and exits 4, so that stage was reported failed on any machine
  without TF2 installed — which is most of them.

## Other fixes

- **Update-check log spam.** A regex variant with no empty alternative made the failure
  path re-arm every frame: 1205 log lines in 25 s, now 49 in 12 s.
- **Identity retargeted** to this fork — README links, sponsors, the Help menu's GitHub
  link, the update check, and the config schema and update URLs. Legacy owners are still
  accepted so existing configs keep working.

## Not covered

Worth stating plainly, because a green gate is a narrower claim than it looks:

- `ci-local.sh` covers compilation and unit behaviour. It does **not** launch the app,
  exercise the Steam Linux Runtime sniper path, or touch any GPU/render code. Those are
  manual on both platforms.
- Windows has had one live session against one server. No soak test, no mode variety.
- Linux live testing is still to be done against these changes.
- One cosmetic RCON issue remains on Windows: an authenticated socket can abort during
  teardown if the launch configuration changes underneath it. It did not reproduce across
  three deliberate attempts, is self-recovering, and does not occur in normal use.
